## Private archive contract

**Proposed destination:** `/Users/ivanpaudice/Library/Application Support/Re-New/archives/strategic-pdr`, owned by Ivan, outside this public application repository and the iCloud `Progetti` workspace. It has not been provisioned or filled in this build. Before a separately authorized live export, #214 must verify the existing operator-approved parent, create the exact destination with owner-only `0700` permissions, verify local access/recovery ownership and freeze new PDR writes. No new cloud service or upload is part of this plan. Archive files use `0600` permissions; the tool rejects a symlink, non-private/wrong-owner destination or a destination inside the application checkout.

`scripts/pdr-archive.ts` is an explicit local operator tool. `export` requires a supplied private destination, separate live-export confirmation, source-frozen assertion, explicit expected WAVE project ref and approved credentials in environment variables. `PDR_ARCHIVE_PG_CA_PEM` must contain an operator-approved trusted PostgreSQL CA certificate from the approved local source; it is not committed, logged or supplied by this build. Before any connection, preflight binds the direct or pooler PostgreSQL identity and HTTPS Storage endpoint to the approved WAVE project `iiuqcdnmxhtyispnykgf`, checks service-role key shape, strips only an `sslmode=require` hint, and configures verified PostgreSQL TLS with the supplied CA. Certificate and hostname validation happen at the TLS handshake, which has not been attempted in this build. It rejects plaintext, mismatched project or SSL-override options. An opaque Supabase secret key cannot be locally proven valid; Supabase must still validate it at download. The build and CI never invoke export. It reads complete original rows from all six `pdr_*` tables, `wave_pdr_governance_capabilities`, `wave_pdr_history_attachments`, `wave_pdr_screening_records`, all `pdr_screening` AI runs and their events, historical governance snapshots/current pointer, and inventories of both `pdr-attachments` and `pdr-intake-attachments` buckets. It copies actual bytes from **both** buckets. These are full source rows: original text/conversation, disposition, IDs, timestamps, references, Work Card replacement/source relations, screening evidence and optional GitHub provenance remain as stored. No request is imported to GitHub or selected for carry-forward.

The archive has private JSONL datasets, byte files, a private reference index (`pdr:goal/<slug>`, `pdr:milestone/<slug>`, `pdr:proposal/<UUID>`, `pdr:request/<UUID>`, `pdr:work-card/<UUID>`, `W-###` and `pdr:legacy-code/<code>`), per-dataset and per-object SHA-256 digests, counts and a manifest digest. An old W-code resolves when unique; a collision with a current W-number or another legacy code is reported as ambiguous, requiring lookup by original UUID. Export checks a repeat database snapshot and then a second source read for changes; a source freeze is still required because storage can change independently. `verify` recomputes every content and byte digest, checks table/object counts and original relationships, including proposal conversion references, proves registered attachments have existing bytes and matching sizes, and checks saved checksums when present. New staff attachments may have a null source checksum, so the tool computes and stores the digest from the **downloaded bytes**. All storage objects are preserved, including unlinked legacy objects; their count is surfaced for #214 review. A missing linked object or parent blocks archive acceptance. Legacy inline attachment JSON stays in the full row even where no private attachment link exists; #214 must reconcile any such source reference and external/legacy byte before declaring real completeness.

Operator commands after separate live authority (never in normal build):

```text
pnpm exec tsx scripts/pdr-archive.ts export --dest <private-root> --expected-project-ref iiuqcdnmxhtyispnykgf --confirm-live-export issue-214-authorized --source-frozen yes
pnpm exec tsx scripts/pdr-archive.ts verify --archive <archive-directory>
pnpm exec tsx scripts/pdr-archive.ts lookup --archive <archive-directory> --ref W-012
pnpm exec tsx scripts/pdr-archive.ts extract --archive <archive-directory> --ref pdr:proposal/<UUID> --dest <private-root>
pnpm exec tsx scripts/pdr-archive.ts extract-object --archive <archive-directory> --bucket pdr-attachments --name <original-storage-name> --dest <private-root>
```

`lookup` prints only ID and attachment count; `extract` writes the original row and linked bytes inside another private local directory. For legacy bucket objects without a modern attachment row, the private `storage_objects` dataset identifies the original name; `extract-object` retrieves its verified bytes and reference. Do not paste archive contents, storage names, raw manifests or private paths into GitHub/Slack. GitHub may receive only safe counts, digest, operator/time and pass/fail evidence. Synthetic fixture tests prove retrieval from both buckets, byte tamper rejection, missing-reference rejection and private permissions; they do not prove any real export or live archive. A separate backup/recovery copy must retain equivalent confidentiality before #214 can accept production retirement.

## On-request founder summary

An authorized person asks Ivan/Codex for a report; there is no PDR page, scheduled task, refresh, new service or default distribution. At report time, check the **accepted** Strategy Registry revision, current GitHub Product Changes, Decisions and their exact release proof. Verify audience access before including private issue links. `lib/founder-summary.ts` only classifies supplied verified facts; it performs no fetch, storage or send. A report states its date and source-check time, strategic direction, delivered outcomes, upcoming scope and decisions needing Ivan. It counts each Product Change once and gives Ticket progress separately. It does not infer release from `Done`, closure, `updatedAt`, a PR or screenshot; production release needs the exact commit, live verification time and linked proof. That verification time cannot postdate either the checked GitHub facts or the report. Missing closure dates stay unknown. Cancelled and superseded changes stay distinct; reopened and partial work remain upcoming. KPI-001 is not an accepted measured actual and no KPI achievement follows from delivery status.

Fixture example (illustrative IDs, no claim about live work): a Product Change closed on 26 September with exact production proof is **released**; a second closed without proof is **closed, release unverified** even if its close date is unknown; separate cancelled and superseded changes are excluded from delivered totals; a reopened change remains upcoming; a change with one closed and one open Ticket is **partial**, counted once. A `Needs Ivan` Decision appears under decisions needed. This contract is exercised in `lib/__tests__/founder-summary.test.ts`. Drafting the summary does not authorize sending it.
