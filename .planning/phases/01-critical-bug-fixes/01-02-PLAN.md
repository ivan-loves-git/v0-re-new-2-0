Output: Admin scoring edits persist correctly with proper error handling for RLS failures.
</objective>

  <name>Task 1: Add RLS failure detection to updateTier1Answers</name>
  <files>lib/actions/repreneurs.ts</files>
  <action>
    The `updateTier1Answers` function (lines 605-689) uses `.update().eq()` without verification. Chain `.select().single()` after the update to detect RLS silent failures.

    Find (around line 612-615):
    ```typescript
    const { error: updateError } = await supabase
      .from("repreneurs")
      .update(answers)
      .eq("id", id)
    ```

    Replace with:
    ```typescript
    const { data: updateResult, error: updateError } = await supabase
      .from("repreneurs")
      .update(answers)
      .eq("id", id)
      .select()
      .single()

    if (!updateResult && !updateError) {
      throw new Error("Update failed: RLS policy may have blocked the operation")
    }
    ```

    Similarly, update the score update block (around line 672-678):
    ```typescript
    const { error: scoreError } = await supabase
      .from("repreneurs")
      .update({
        tier1_score: scoreBreakdown.total,
        tier1_score_breakdown: scoreBreakdown,
      })
      .eq("id", id)
    ```

    Replace with:
    ```typescript
    const { data: scoreResult, error: scoreError } = await supabase
      .from("repreneurs")
      .update({
        tier1_score: scoreBreakdown.total,
        tier1_score_breakdown: scoreBreakdown,
      })
      .eq("id", id)
      .select()
      .single()

    if (!scoreResult && !scoreError) {
      throw new Error("Score update failed: RLS policy may have blocked the operation")
    }
    ```

    This ensures that if RLS blocks the update silently (returning empty array instead of error), we detect it and throw an error that propagates to the UI.
