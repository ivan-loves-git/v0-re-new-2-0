# Phase 8.1: Stabilize Demo Blockers and Searchable Selectors

**Status:** Planned
**Parent Phase:** 8 - Post-demo workflow MVP
**Requirements:** POSTDEMO-01, POSTDEMO-06
**Depends on:** Phase 7, Phase 8 research

## Goal

Staff can complete the workflows that visibly broke or slowed down during the founder demo: portal access enablement, repreneur selection, opportunity edit save feedback, and slow opportunity/dashboard loading.

## Current-code Context

- Portal access is handled by `lib/actions/portal-access.ts` and `components/repreneurs/portal-access-card.tsx`.
- Portal preview uses `components/repreneurs/staff-portal-preview-selector.tsx`.
- Opportunity recommendation selection uses `components/opportunities/opportunity-matches-panel.tsx`.
- Opportunity edit/save behavior lives in `components/opportunities/opportunity-form.tsx` and `lib/actions/opportunities.ts`.
- Dashboard performance work appears to be in progress in the dirty worktree. Inspect those changes before adding anything.

## Tasks

1. Reproduce the portal access enablement error on a test repreneur.
   - Verify user creation, credential account creation, repreneur role linkage, and password-reset email behavior.
   - Make the action return a clear staff-facing error when any step fails.
   - Avoid leaving a misleading "enabled" state if email setup fails.

2. Fix opportunity edit save feedback.
   - Replace the current stuck `isSubmitting` success path with a result-returning action flow or `useActionState`.
   - Keep create redirect behavior intact.
   - Show a clear success or error toast after edit.

3. Add a reusable staff-side repreneur combobox.
   - Use the existing shadcn/Radix/cmdk pattern already available in the app.
   - Keep keyboard search and empty-state behavior.
   - Preserve form compatibility for places that need a submitted `repreneur_id`.

4. Replace the two highest-friction selectors first.
   - Portal preview repreneur selector.
   - Opportunity recommendation repreneur selector.

5. Investigate slow opportunity edit and dashboard loading.
   - Review the existing dirty dashboard snapshot/index work before changing code.
   - Add only targeted fixes needed for the demo workflows.
   - If performance work belongs to a separate pending branch, record that rather than duplicating it.

## Acceptance Criteria

- Staff can enable, resend, and disable portal access for a test repreneur without a generic failure.
- Opportunity edit save feedback always exits loading state after success or error.
- Portal preview and opportunity recommendation selectors can search by repreneur name/email.
- Slow-load findings are classified as fixed, already covered by existing dirty work, or deferred with a specific reason.
- No unrelated dirty app changes are reverted.

## Verification

- `npm run lint`
- `npm run build`
- Browser UAT with the stored staff credentials:
  - Open a repreneur profile and run portal access actions.
  - Open portal preview and search/select a repreneur.
  - Open an opportunity recommendation panel and search/select a repreneur.
  - Edit an opportunity and confirm the save button resets after success.
  - Record load-time observations for dashboard and opportunity edit pages.

## Executive Summary

This slice fixes the issues that would make the platform feel unreliable in front of Bertrand and Colin. It turns the obvious demo pain points into stable, searchable, and testable staff workflows.

The work stays close to existing screens and actions. It is about making what is already there usable under real operating conditions, not changing the product model.
