# Phase 8.4: Info Memo Stage and NDA Request Workflow

**Status:** Completed locally 2026-05-22
**Parent Phase:** 8 - Post-demo workflow MVP
**Requirements:** POSTDEMO-04, POSTDEMO-06
**Depends on:** 08-02 M&A contact reliability, 08-03 match visibility

## Goal

When a repreneur is interested and staff validates the pursuit, staff can request the M&A firm's NDA/info memo with the right repreneur context, then track that the info memo was received before the intermediary meeting.

## Current-code Context

- `OpportunityPursuitStage` currently has `interest`, `intermediary_meeting`, `seller_meeting`, `loi`, `closed`, and `dropped`.
- `scripts/049_opportunity_pursuit_stages.sql` created the pursuit-stage enum.
- `lib/actions/opportunity-matches.ts` controls stage validation and staff-editable stages.
- `components/opportunities/opportunity-pursuit-panel.tsx` renders stage options.
- `lib/utils/opportunity-journey.ts` maps stages into derived journey labels.
- `lib/actions/ma-workflows.ts`, `components/opportunities/opportunity-ma-workflow-panel.tsx`, and `ma_source_interactions` already support M&A email drafting, sending, and logging.

## Tasks

1. Add the new pursuit stage.
   - Add a migration for `info_memo_received`.
   - Place it after `interest` and before `intermediary_meeting` in UI ordering.
   - Do not add speculative stages unless implementation research shows they are needed.

2. Thread the stage through the app.
   - Update TypeScript types.
   - Update pursuit-stage labels/options.
   - Update action allow-lists.
   - Update journey derivation.
   - Update pure unit tests for journey mapping.

3. Add or specialize an M&A workflow email for NDA/info memo request.
   - Reuse the existing M&A workflow send/logging stack.
   - The email should request the NDA/info memo from the M&A firm.
   - Include opportunity context and repreneur profile/fiche de cadrage context where available.
   - Block sending clearly when M&A contact email or active pursuit context is missing.

4. Connect the flow to validated pursuit.
   - After staff validates a pursuit, make the next action visible: prepare/request NDA/info memo.
   - Log the outbound message in `ma_source_interactions`.
   - Keep the rule that the M&A firm requires the candidate/repreneur to sign its NDA; Re-New does not replace this with a generic NDA.

5. Add lightweight reminders.
   - Derive reminders from active pursuits that have not advanced after a few days.
   - Prefer existing stage and interaction timestamps over a new reminders table.
   - Show the reminder in the opportunity/dashboard workflow where staff already works.

## Acceptance Criteria

- Staff can set a pursuit to "Info memo received" before intermediary meeting.
- Journey labels and pursuit history remain coherent after the new stage is added.
- Staff can prepare/send an M&A firm request for NDA/info memo using active pursuit context.
- The outbound request is logged against the opportunity/source.
- Missing M&A email or missing pursuit context blocks the send with a clear message.
- A reminder appears or is derivable when the process has not moved after the agreed threshold.

## Executive Summary

This slice targets Bertrand's biggest manual burden from the demo: coordinating between repreneurs and M&A firms after interest is confirmed. The platform should help prepare the request, track the next state, and remind the team when the process stalls.

The plan reuses the existing M&A email workflow instead of building a new communication system. It adds one carefully named stage and keeps the legal rule clear: each M&A firm still controls its own NDA.
