# Phase 8.3: Matching Visibility in Both Directions

**Status:** Completed locally 2026-05-22
**Parent Phase:** 8 - Post-demo workflow MVP
**Requirements:** POSTDEMO-03, POSTDEMO-06
**Depends on:** 08-01 selector improvements

## Goal

Staff can understand matching from either work surface: from an opportunity they can see recommended repreneurs, and from a repreneur they can see associated opportunities, match scores, and statuses.

## Current-code Context

- `lib/actions/opportunity-matches.ts` lists matches by opportunity but not yet by repreneur.
- `components/opportunities/opportunity-matches-panel.tsx` already displays score, recommendation, reasons, and status for an opportunity.
- `components/opportunities/opportunity-detail.tsx` already receives opportunity matches and keeps recommendations inside a deeper tab.
- `app/(dashboard)/repreneurs/[id]/page.tsx` does not currently show associated opportunities.
- `components/opportunities/repreneur-opportunity-list.tsx` may be reusable or adaptable for a compact staff-side list.

## Tasks

1. Add a reverse match query.
   - Add `listOpportunityMatchesForRepreneur(repreneurId)` or equivalent server action.
   - Return opportunity reference/title, status, platform score/recommendation, human recommendation, match status, pursuit stage, and dates.
   - Use existing indexes or pending performance migration where available.

2. Add a repreneur-detail opportunity matches section.
   - Place it where staff naturally review a repreneur profile, without overcrowding the existing profile content.
   - Show associated opportunities/matches with score, status, and a link to each opportunity.
   - Include an empty state that tells staff when no matches exist.

3. Surface recommended repreneurs on opportunity overview.
   - Add a compact overview card/list using the already loaded `matches`.
   - Show the top recommended repreneurs with status and score.
   - Link to the full Recommendations tab and to repreneur profiles.

4. Keep matching logic unchanged.
   - Do not redesign scoring.
   - Do not add AI matching.
   - Do not change active-pursuit locking rules in this slice.

## Acceptance Criteria

- Repreneur profile pages show associated opportunities and match context.
- Opportunity overview shows recommended repreneurs without requiring staff to find a deeper tab first.
- Existing recommendation management still works.
- Empty states are clear and do not look like loading failures.
- No schema change is required unless implementation research proves one is necessary for performance.

## Verification

- `npm run lint`
- `npm run build`
- Browser UAT:
  - Open a repreneur with known opportunity matches and confirm reverse list.
  - Open a repreneur with no matches and confirm empty state.
  - Open an opportunity with multiple recommendations and confirm overview summary.
  - Create or edit a recommendation and confirm both opportunity and repreneur views update after refresh.

## Executive Summary

This slice gives the team the missing "other side" of matching. Bertrand can start from a deal and find repreneurs, while Colin can start from a repreneur and see which opportunities are already connected.

The work reuses the existing match data. It improves visibility and operating confidence without changing the matching algorithm.
