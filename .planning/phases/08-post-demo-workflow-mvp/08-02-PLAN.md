# Phase 8.2: Opportunity Creation, Validation, and Field Cleanup

**Status:** Planned
**Parent Phase:** 8 - Post-demo workflow MVP
**Requirements:** POSTDEMO-02, POSTDEMO-05, POSTDEMO-06
**Depends on:** 08-01 where form feedback changes overlap

## Goal

Staff can create a real opportunity from the existing Excel-style structure with clear mandatory fields, reliable M&A contact storage, and a simple entrepreneur-visible teaser summary. Confusing field labels are removed, renamed, or hidden from the main flow.

## Current-code Context

- `app/(dashboard)/opportunities/new/page.tsx` already exists.
- `components/opportunities/opportunity-form.tsx` already captures opportunity data and M&A source/contact data.
- `lib/actions/opportunities.ts` already upserts M&A source data through `upsertSourceFromForm`.
- `anonymized_description` is the current database field for entrepreneur-visible description.
- `source_notes`, `source_visibility`, `staff_notes`, and visibility/anonymization labels are confusing in the current UI.

## Tasks

1. Make opportunity creation easy to find.
   - Add a clear "Create opportunity" entry point where staff naturally look for it.
   - Candidate surfaces: opportunity list/find/groups header and opportunity dashboard quick action.
   - Do not create duplicate routes if `/opportunities/new` is already correct.

2. Define required fields from the existing Excel structure.
   - Minimum candidate set: reference, sector/activity, location/region, revenue, EBITDA, headcount, date added, M&A firm/source, contact name, contact email, and teaser summary.
   - Check the current import mapper and form fields before locking the exact validation list.
   - Prefer required warnings and field-level errors over broad database constraints unless the schema already guarantees the field.

3. Add server-side and client-side validation.
   - Keep server-side validation authoritative.
   - Use HTML `required` and helpful field errors where practical.
   - Return structured errors that the form can display without losing entered data.

4. Verify and harden M&A source storage.
   - Confirm firm, contact name, email, phone, notes, and `source_id` linkage persist correctly.
   - Keep the existing `ma_sources` model unless implementation research finds a real data bug.
   - Make contact email validation explicit enough to avoid unusable M&A workflows later.

5. Add or relabel the entrepreneur-visible teaser field.
   - Use the current `anonymized_description` column if a DB rename would add unnecessary risk.
   - Change staff-facing UI copy to "Teaser summary" or similarly clear language.
   - Make clear that info memo storage is not part of this phase.

6. Clean confusing fields.
   - Review "anonymized description", "source notes", "visibility", "staff only", "approved", and "revealed" copy in opportunity detail/edit.
   - Remove/hide fields that do not drive current workflow.
   - Keep internal staff notes only if they are useful for Colin and Bertrand working together; otherwise move them out of the primary form.

7. Park import automation.
   - JSON import from ChatGPT output is recorded as future scope for V4.
   - Full PDF-to-opportunity AI ingestion remains future scope.

## Acceptance Criteria

- A staff user can find and open the create-opportunity form without knowing the URL.
- Missing required opportunity fields produce clear warnings before save.
- M&A source firm, contact name, and contact email persist and appear on the opportunity after save.
- Entrepreneur-visible teaser text is clearly labeled and saved.
- Info memo storage is not added.
- JSON import and PDF ingestion are explicitly left out of the MVP implementation.

## Verification

- `npm run lint`
- `npm run build`
- Browser UAT:
  - Create an opportunity with missing fields and confirm validation.
  - Create an opportunity with all required fields and confirm redirect/detail state.
  - Edit the same opportunity and confirm M&A source/contact persistence.
  - Confirm the entrepreneur-visible teaser appears in staff view and does not expose M&A source details.

## Executive Summary

This slice turns opportunity creation into a real operating workflow. Staff should be able to enter the same information Bertrand already structures in Excel, save it cleanly, and trust that M&A contact details are ready for follow-up.

The plan deliberately avoids expensive AI ingestion and info memo storage. The immediate value is a reliable manual path that can later become more automated once the data shape is proven.
