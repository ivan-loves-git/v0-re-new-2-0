## Goal

Prove the post-demo MVP works in the browser as a real staff workflow, update project memory, and keep future ideas out of the current build.

## Tasks

1. Run full technical verification.
   - `npm run lint`
   - `npm run build`
   - Any focused unit tests added for pursuit stage or journey logic.
   - Confirm no TypeScript issue is hidden behind `next.config.mjs` ignoring build errors.

2. Run browser UAT as staff.
   - Use the stored approved credentials from project instructions.
   - Verify portal access actions.
   - Verify searchable selectors.
   - Verify opportunity create/edit validation and save feedback.
   - Verify M&A source/contact persistence.
   - Verify reverse matching from repreneur profile.
   - Verify recommended repreneurs on opportunity overview.
   - Verify active pursuit, NDA/info memo request, info memo stage, and reminders.

3. Run repreneur portal smoke checks where affected.
   - Confirm entrepreneur-visible teaser context is visible where intended.
   - Confirm M&A source/internal data is not exposed.
   - Confirm portal preview matches real portal behavior for affected opportunity fields.

4. Classify performance findings.
   - Confirm whether slow dashboard/opportunity edit loading is fixed in this phase, covered by existing pending performance work, or deferred.
   - Record exact deferred item if not fixed.

5. Update project-facing memory.
   - Update Phase 8 summaries after execution.
   - Update `REQUIREMENTS.md` statuses only after verified completion.
   - Update in-app roadmap if the work changes what the Re-New team sees.
   - Mirror committed scope into Linear if the matching project/issues exist.

6. Preserve parking lot items.
   - JSON import path from ChatGPT output stays V4/backlog.
   - Full PDF-to-opportunity AI ingestion stays future scope.
   - Full HTML email editor stays future scope.
   - Intermediary portal and broader Wavy AI assistant stay future scope unless separately approved.

## Acceptance Criteria

- All Phase 8 implementation slices have passing verification or documented blockers.
- Browser UAT covers the exact workflows discussed in the founder demo.
- No future-scope item is accidentally included in the MVP.
- Roadmap, requirements, summaries, and backlog notes match the verified product state.
- Ivan can explain the outcome to Bertrand in simple operational terms.

## Verification Evidence to Record

- Build/lint command results.
- Browser UAT date, environment, build number if production is tested, and pass/fail notes.
- Any remaining defects with severity and next action.
- Any deferred item with the reason it is not in Phase 8.

## Executive Summary

This slice is the release gate. It makes sure the work is not just present in code, but actually works in the browser for the staff workflows Bertrand and Colin will use.

It also keeps the project disciplined by separating the MVP from attractive future automation ideas. That protects momentum and makes the next conversation with the founders clearer.
