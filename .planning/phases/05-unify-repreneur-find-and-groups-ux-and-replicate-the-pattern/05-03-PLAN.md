# Plan 05-03: Build Opportunity Find and Groups Pages from the Shared Pattern

**Status:** planned
**Phase:** 5 - Unified Find and Groups Work Surfaces

## Goal

Give opportunities the same operating surfaces as repreneurs: one page to find records across the whole opportunity base, and one page to manage opportunities by meaningful groups.

## Scope

- Add opportunity Find and Groups routes.
- Keep the current opportunity records page available unless the new IA deliberately redirects it.
- Add sidebar links under Opportunities once the routes exist.
- Use the derived opportunity journey as a primary tag.
- Choose staff-useful columns rather than exposing every field.

## Proposed Routes

- `/opportunities/find` - flat searchable opportunity table.
- `/opportunities/groups` - grouped opportunity operating table.
- `/opportunities` - preserve as Records during the transition unless a later decision replaces it.

## Candidate Groups

- Draft
- Live in inventory
- Matching
- Proposed
- Interest received
- Active pursuit
- Meeting / LOI
- Paused
- Closed / dropped / archived

The final grouping should be practical for staff scanning, not a literal one-group-per-status if that creates clutter.

## Candidate Columns

- Reference / title
- Journey label
- Availability status
- Visibility
- Sector / activity
- Location
- Revenue, EBITDA, headcount
- Date added / freshness
- Source label or source type
- Active pursuit repreneur
- Pending review or match count signal

## Tasks

1. Extend opportunity data loading to include the match and pursuit summary needed for journey labels and group buckets.
2. Build an opportunity Find table using the same page/table/filter/pagination pattern as repreneur Find.
3. Build an opportunity Groups table using the same grouped/paginated pattern as repreneur Groups.
4. Add journey badge, availability badge, visibility badge, and compact deal-size cells.
5. Add top filters for journey, availability, visibility, sector, location, source, freshness, and active pursuit where useful.
6. Add sidebar links in the Opportunities group.

## Acceptance Criteria

- Staff can reach opportunity Find and Groups from the sidebar.
- Opportunity Find supports cross-record search and filtering.
- Opportunity Groups gives clear operating buckets and counts.
- Journey label is visible as a primary tag.
- Existing opportunity detail routes remain reachable.
- The page does not expose staff-only source detail outside staff routes.

## Verification

- Run `npm run lint`.
- Run `npm run build`.
- Browser test `/opportunities/find`, `/opportunities/groups`, and existing `/opportunities`.
- Test filters, grouping, pagination, row navigation, and active pursuit labels.

## Executive Summary

This plan gives opportunities the same daily operating structure that repreneurs already have. The team will be able to search the whole opportunity base or work from grouped deal-flow buckets.

The main product improvement is the journey tag. Instead of asking the team to mentally combine availability, match, and pursuit status, each opportunity gets one clear label for scanning.
