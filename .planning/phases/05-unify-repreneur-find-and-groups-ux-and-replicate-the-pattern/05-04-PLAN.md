# Plan 05-04: Validate UX Consistency, Responsiveness, and Navigation

**Status:** planned
**Phase:** 5 - Unified Find and Groups Work Surfaces

## Goal

Verify that the four work surfaces behave coherently in the actual app before the phase is considered done.

## Scope

- Browser UAT for repreneur Groups, repreneur Find, opportunity Groups, and opportunity Find.
- Verify navigation, filters, grouping, pagination, mobile layout, and row detail access.
- Update in-app Guidelines or Roadmap if the implemented labels differ from the planned labels.
- Record UAT evidence in the phase directory.

## Tasks

1. Run static checks and production build.
2. Start local app and log in with the approved staff credentials.
3. Test `/repreneurs`, `/repreneurs/explore`, `/opportunities/groups`, `/opportunities/find`, and `/guide/guidelines`.
4. Check desktop and mobile widths for filter wrapping, table readability, tag clarity, and pagination.
5. Confirm opportunity journey labels match the Guidelines page.
6. Record findings and fixes in `05-UAT.md`.
7. Update roadmap/requirements status only after browser verification passes.

## Acceptance Criteria

- All four work surfaces are reachable from navigation.
- Tables and filters are readable on desktop and mobile.
- Pagination and grouped counts behave predictably.
- Opportunity journey labels are consistent between code and Guidelines.
- No login-wall testing shortcut is used; the app is tested after staff login.
- UAT evidence exists before completion.

## Verification

- `npm run lint`
- `npm run build`
- Browser UAT with staff login.
- Confirm footer build number when testing production after deployment.

## Executive Summary

This plan makes sure the new work surfaces are not just coded, but usable by the Re-New team. It checks the real pages, real navigation, and real responsive layouts.

The phase should only close when the four pages feel like one coherent system and the Guidelines page matches what the app actually shows.
