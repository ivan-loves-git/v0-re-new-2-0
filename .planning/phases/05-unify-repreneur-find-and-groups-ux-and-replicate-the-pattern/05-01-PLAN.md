# Plan 05-01: Lock Shared Table, Filter, Pagination, and Journey-Label Design Contract

**Status:** planned
**Phase:** 5 - Unified Find and Groups Work Surfaces

## Goal

Define the shared UX contract before implementation so repreneur and opportunity pages become coherent without forcing a brittle one-size-fits-all component.

## Scope

- Audit the current repreneur Groups and Find table structures.
- Define the shared page anatomy: header actions, filter bar, active filters, table wrapper, row behavior, empty states, group headers, pagination, export action.
- Define the derived opportunity journey helper contract.
- Define the tag/color system for repreneur lifecycle, repreneur journey, opportunity journey, and opportunity availability.
- Decide which patterns should be shared as components and which should remain domain-specific.

## Tasks

1. Review `components/repreneurs/repreneur-table.tsx`, `components/repreneurs/repreneur-explore-table.tsx`, and `components/opportunities/opportunity-table.tsx`.
2. Create or update a lightweight design note in the phase directory describing shared UX rules.
3. Add the opportunity journey derivation map in TypeScript, preferably near `lib/types/opportunity.ts` or a small utility imported by opportunity tables.
4. Confirm the derived map handles draft, paused, archived, closed, no matches, shortlisted, proposed, interested, active pursuit, pursuit stages, and dropped states.
5. Identify reusable component candidates, but defer extraction unless two pages need the same behavior immediately.

## Acceptance Criteria

- A written design contract exists for Find and Groups behavior.
- Opportunity journey labels are deterministic and covered by unit-level or simple function tests if a test pattern exists.
- No database migration is introduced for a manual journey field.
- Implementation plans 05-02 and 05-03 have enough detail to proceed without redesigning the UX again.

## Verification

- Run `npm run lint`.
- Run `npm run build` after helper code is added.
- Manually inspect the journey map against existing opportunity status, match status, and pursuit stage values.

## Executive Summary

This plan creates the operating rules for the new work surfaces before we touch the bigger pages. It makes clear what should look the same across repreneurs and opportunities, and what should stay specific to each domain.

The most important decision is that opportunity journey is a visible label, not a new manual field. The team gets a simple status to scan, while the system keeps the existing source facts underneath.
