# 03-04: Launch/Demo Checklist and V3 Deferred Backlog

## Goal

Package June V2 for demo/release by writing the launch checklist and making the deferred V3 backlog explicit.

## Scope

- Write a practical demo checklist for the staff workflow and repreneur-facing workflow.
- Write release checks for build, browser smoke, Supabase data, Vercel deploy monitoring, and rollback.
- Write post-launch monitoring items.
- Create a V3 backlog that clearly separates deferred scope from June V2.
- Mark Phase 3 and the June V2 milestone as implementation-complete in GSD state.

## Out of Scope

- No new product feature code.
- No new schema changes.
- No Linear issue creation in this slice.
- No V3 planning beyond a backlog-ready list.

## Implementation Steps

1. Create the launch/demo checklist artifact.
2. Create the V3 deferred backlog artifact.
3. Update project and milestone state to show June V2 implementation complete.
4. Run a final build check.
5. Commit and prepare the branch for push/merge.

## Acceptance Criteria

- The demo checklist covers staff opportunity management, matching, pursuit, NDA/documents, KPI/freshness, and repreneur portal surfaces.
- The release checklist covers pre-merge, Vercel deploy, smoke, rollback, and known limitations.
- The V3 backlog includes deferred AI, automation, CRM, portal, legal, reporting, and self-service items.
- GSD roadmap/state show Phase 3 complete.
- Build passes.

## Executive Summary

This final slice turns the built product into something the team can actually use and present. It says what to show, what to verify before release, and what to watch after deploy.

It also protects scope discipline: postponed ideas are not lost, but they are clearly outside June V2 and ready to become V3 work after the basics are validated.
