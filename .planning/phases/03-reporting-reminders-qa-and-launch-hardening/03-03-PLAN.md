# 03-03: End-to-End QA With Realistic Data

## Goal

Verify that the June V2 workflow works end to end with the current realistic demo data before launch/demo preparation.

## Scope

- Verify staff dashboard KPIs and freshness reminders render on the local app.
- Verify staff opportunity list and detail screens show opportunity records, matching, pursuit, and documents tabs.
- Verify staff review queue exists for repreneur responses.
- Verify legacy `/my-opportunities` routing and `/portal/*` access boundaries still behave consistently.
- Verify database-level demo data includes opportunities, repreneur matches, active pursuit, stage/NDA states, and approved documents.
- If the current demo dataset lacks an end-to-end pursuit path, seed the minimum marked demo records needed to test it.
- Confirm build status and known test limitations.

## Out of Scope

- No new feature work unless QA finds a blocker.
- No destructive cleanup.
- No new Supabase migration.
- No milestone closure; that remains after 03-04.

## Implementation Steps

1. Run the production build.
2. Use browser smoke checks against the local app for staff dashboard, opportunities, opportunity detail, reviews, and routing guards.
3. Run read-only Supabase data checks for demo opportunity/match/document coverage.
4. If the dataset is missing active pursuit, stage, NDA, or document coverage, add minimal marked demo records.
5. Re-run the data checks.
6. Record pass/fail results in a phase UAT artifact.
7. Update GSD state and write the completion summary.

## Acceptance Criteria

- Production build passes.
- Browser checks confirm the main staff workflow pages render.
- Browser checks confirm staff users cannot use repreneur portal routes.
- Read-only data checks confirm realistic demo opportunities, matches, active pursuit, NDA state, and approved document coverage exist.
- Any residual risk is documented.

## Executive Summary

This slice is the confidence check before launch readiness. It does not add product scope; it proves that the pieces already built can be shown and operated together.

The result should tell us whether the June V2 workflow is demo-safe, and which risks still need to be named before closing the milestone.
