# 03-01: Operational KPI Dashboard

## Goal

Add an internal-only opportunity KPI section to the staff dashboard so the team can see deal-flow health without opening every opportunity one by one.

## Scope

- Add a server-side KPI query for opportunity operating metrics.
- Show counts for active intermediaries, active opportunities, introductions, active pursuits, seller meetings, LOIs, dropped deals, and closed deals.
- Show a simple conversion/readiness view so staff can understand whether the funnel is healthy.
- Keep the view staff-dashboard-only for June.

## Out of Scope

- No external reporting page.
- No polished investor report export.
- No automatic reminders; stale opportunity reminder is plan 03-02.
- No change to the repreneur portal.

## Implementation Steps

1. Add an opportunity KPI data action that reads from `opportunities`, `ma_sources`, `opportunity_matches`, and `opportunity_pursuit_events`.
2. Build a dashboard component using existing shadcn `Card`, `Badge`, `Progress`, and `Table` primitives.
3. Insert the KPI section near the top of `/dashboard`, before older repreneur-pipeline analytics.
4. Verify with build, focused typecheck, and browser smoke on `localhost:3012/dashboard`.
5. Update GSD state and write the completion summary.

## Acceptance Criteria

- Staff dashboard shows the June KPI counts requested in `KPI-01`.
- The section does not expose to `/portal/*` or any repreneur route.
- Counts are derived from the Phase 1/2 opportunity workflow, not hardcoded.
- Build passes.
- Existing full typecheck baseline remains no worse for files touched in this plan.

## Executive Summary

This slice gives the Re-New team a simple control panel for the deal workflow we just built. It answers the practical daily question: how many opportunities, introductions, meetings, LOIs, dropped deals, and closed deals are in motion?

The implementation stays internal and operational. It is not a polished reporting product yet; it is the staff-facing dashboard needed to run June V2 with confidence.
