# Phase 1.1 Context: Testing Environment and Release Protocol

## Why This Phase Exists

Phase 1 added real database-backed opportunity features. Continuing to Phase 2 without a testing and release protocol would increase product and data risk.

This phase creates the operating discipline for Re-New development:
- where migrations are applied,
- how test data is created,
- how UAT is recorded,
- when branches are pushed or merged,
- how rollback is handled.

## Product Principle

Re-New data is more valuable than velocity. Code can be reverted in GitHub; database changes need explicit backup, environment, and rollback decisions.

## Decision History

The first recommended default was a separate Supabase test project.

Ivan later confirmed on 2026-05-17 that Supabase charges for another project in the current setup, so Phase 1.1 will use the same/current Re-New Supabase project.

## Locked Decision

Phase 1.1 uses the same/current Re-New Supabase project with a controlled migration protocol.

This means:
- Phase 1 migrations are approved only because they are additive.
- No destructive SQL is allowed against existing schema or existing non-UAT data.
- Fake or sanitized UAT data must be visibly marked.
- The worktree `.env.local` must point to the approved current Supabase project and remain uncommitted.
- Backup/rollback route must be recorded before migration.
- Phase 2 remains blocked until the test environment and UAT gate pass.

## In-Scope

- Environment decision and documentation.
- Worktree test setup.
- Supabase migration safety protocol.
- Phase 1 UAT checklist and result log.
- GitHub/GSD/Linear release responsibilities.
- Applying Phase 1 additive migrations to the approved current Supabase project.
- Backup/rollback note before migration.
- UAT record labeling and cleanup.

## Out-of-Scope

- Building Phase 2 features.
- Production deployment.
- Full CI/CD automation.
- Creating a new paid Supabase project.
- Running destructive SQL.
- Deleting existing non-UAT records.
- Large database cloning unless explicitly needed.
