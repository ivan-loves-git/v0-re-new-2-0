# Plan: Investigate and Fix RLS Policies

## Objective

Understand why RLS policies aren't working and fix them permanently.

## Background

- Database has 118 repreneurs (confirmed with service role)
- RLS disabled → data shows ✓
- RLS enabled with policies → data doesn't show ✗
- Policies created but not working

## Investigation Tasks

### Task 1: Check Current RLS State

Query the database to see:
1. Is RLS enabled on repreneurs?
2. What policies currently exist?
3. What roles do policies apply to?

```sql
-- Check RLS status
SELECT relname, relrowsecurity, relforcerowsecurity
FROM pg_class
WHERE relname = 'repreneurs';

-- List all policies on repreneurs
SELECT policyname, permissive, roles, cmd, qual, with_check
FROM pg_policies
WHERE tablename = 'repreneurs';
```

### Task 2: Check User Role

The dashboard uses `createServerClient()` which reads cookies for auth.
Need to verify:
1. What role is the logged-in user using?
2. Is it `authenticated` or something else?

Test query with explicit role:
```sql
-- Test as authenticated role
SET ROLE authenticated;
SELECT count(*) FROM repreneurs;
RESET ROLE;
```

### Task 3: Check for Conflicting Policies

Multiple policies can conflict. Check:
1. Are there DENY policies?
2. Are policies PERMISSIVE or RESTRICTIVE?
3. Is there a policy order issue?

### Task 4: Create Clean Policies

Drop ALL existing policies and create fresh ones:

```sql
-- Nuclear option: drop all policies first
DO $$
DECLARE
    pol RECORD;
BEGIN
    FOR pol IN SELECT policyname FROM pg_policies WHERE tablename = 'repreneurs'
    LOOP
        EXECUTE 'DROP POLICY IF EXISTS "' || pol.policyname || '" ON repreneurs';
    END LOOP;
END $$;

-- Now create clean policies
CREATE POLICY "team_read_all" ON repreneurs
FOR SELECT TO authenticated
USING (true);

CREATE POLICY "team_insert" ON repreneurs
FOR INSERT TO authenticated
WITH CHECK (true);

CREATE POLICY "team_update" ON repreneurs
FOR UPDATE TO authenticated
USING (true) WITH CHECK (true);

CREATE POLICY "team_delete" ON repreneurs
FOR DELETE TO authenticated
USING (true);

CREATE POLICY "public_insert" ON repreneurs
FOR INSERT TO anon
WITH CHECK (true);
```

### Task 5: Verify Fix

1. Enable RLS
2. Test with anon key (should return 0 for SELECT, allow INSERT)
3. Test with authenticated session (should return 118)
4. Test dashboard in browser

## Success Criteria

- [ ] Understand why previous policies failed
- [ ] RLS enabled on repreneurs table
- [ ] Authenticated users see all 118 repreneurs
- [ ] Dashboard works correctly
- [ ] Intake form can still create new repreneurs
