# 02-06: Deal Stage Tracking

## Goal

Re-New staff can track the current operating stage of the validated active pursuit without turning the product into a full CRM.

## Scope

- Add additive Supabase schema for pursuit stage tracking:
  - current stage on `opportunity_matches`
  - lightweight stage history table
- Use the June stage set from `DEAL-04`:
  - `interest`
  - `intermediary_meeting`
  - `seller_meeting`
  - `loi`
  - `closed`
  - `dropped`
- Initialize a validated pursuit at `interest`.
- Move a dropped pursuit to the `dropped` stage when staff uses the existing drop action.
- Add a staff `Pursuit` tab on opportunity detail.
- Show the current active-pursuit stage in the repreneur portal when relevant.

## Out Of Scope

- Full CRM notes and tasks.
- Automatic reminders.
- Notifications.
- NDA status and document gating.
- Multiple active pursuits for the same opportunity.
- Closing accounting, commission, or payment workflow.

## Tasks

1. Add the additive SQL migration.
2. Extend opportunity match types and loaders with pursuit stage fields.
3. Add staff server actions for updating the active pursuit stage.
4. Add a staff pursuit panel with current stage, note, and history.
5. Add portal display of the current active-pursuit stage.
6. Apply and verify the migration against the approved Supabase project.
7. Build, smoke test, update GSD state, commit, and push.

## Success Criteria

- Existing opportunities and matches continue to load after migration.
- Validating a pursuit sets current stage to `interest`.
- Staff can change an active pursuit to intermediary meeting, seller meeting, LOI, or closed.
- Dropping a pursuit records the `dropped` stage and preserves history.
- Repreneurs only see the safe current stage, not staff notes or internal history.

## Executive Summary

This plan adds the missing operating layer after staff validates a repreneur as the active path. The team can now see whether the pursuit is still at interest, has reached intermediary/seller meetings, has an LOI, is closed, or was dropped.

The implementation is intentionally small. We track the current stage and history, but we do not add tasks, reminders, notifications, or a full CRM timeline yet.
