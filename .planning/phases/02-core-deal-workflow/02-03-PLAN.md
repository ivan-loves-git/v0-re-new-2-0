# Plan 02-03: Split Staff Dashboard and Repreneur Portal

## Goal

Repreneurs access deal flow through a separate external portal experience instead of the internal staff dashboard shell.

## Scope

- Add `/portal/deals` for repreneur opportunity access.
- Add `/portal/profile` as a read-only repreneur profile summary with scores, strengths, improvement points, and calls to action.
- Redirect legacy `/my-opportunities` routes away from the old mixed dashboard page.
- Remove `My Deals` from the staff sidebar.
- Route logged-in users to the correct surface after login.
- Add a simple app-user role table so future third-party access can be explicit instead of inferred only from email.

## Non-Goals

- Full repreneur profile editing.
- Seller or M&A firm portals.
- Full staff route migration to `/staff/*`.
- Certification sharing or public profile links.

## Acceptance Criteria

- Staff users keep the internal dashboard experience.
- Repreneur users land in `/portal/deals`.
- Portal pages do not render the staff sidebar.
- Portal opportunity links use `/portal/deals/:matchId`.
- Repreneur profile page is read-only and shows useful profile/value feedback.
- Repreneurs cannot browse internal dashboard routes after login.

## Verification

- Apply additive role migration.
- Run typecheck or capture existing baseline failures.
- Open local portal and staff routes in the browser.
- Confirm legacy `/my-opportunities` no longer renders the old mixed dashboard page.

## Executive Summary

We are separating the product into an internal Re-New operating dashboard and an external repreneur portal. This keeps the June build aligned with the real actors: staff manage the marketplace; repreneurs only see their own curated deals and a controlled profile summary.

The profile page stays read-only for now. It turns existing scoring and readiness data into a motivating view for the repreneur without opening the larger self-service scope too early.
