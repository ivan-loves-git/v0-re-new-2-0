# 02-07: NDA and Repreneur Document Download Flow

## Goal

Re-New staff can control whether the active repreneur pursuit needs an NDA, and the active repreneur can download only the documents staff explicitly approved.

## Scope

- Add additive pursuit-level NDA fields on `opportunity_matches`.
- Use a small June NDA status set:
  - `not_required`
  - `required`
  - `sent`
  - `signed`
  - `waived`
- Let staff update NDA status, select the linked NDA document, and keep an internal NDA note from the opportunity `Pursuit` tab.
- Show NDA status in the repreneur portal.
- Show approved documents only to the active pursuit owner.
- Gate downloads until NDA status is `not_required`, `signed`, or `waived`.
- Serve file downloads through an authenticated portal route instead of exposing storage paths in the UI.

## Out Of Scope

- E-signature.
- Legal negotiation workflow.
- M&A firm portal.
- Inline PDF viewer.
- Automatic document parsing.
- Per-document recipient lists beyond the active pursuit owner.

## Tasks

1. Add the additive SQL migration.
2. Extend opportunity match and portal exposure types.
3. Add staff action for pursuit-level NDA status.
4. Add staff NDA controls to the existing `Pursuit` tab.
5. Add portal NDA/document display.
6. Add a protected document download route.
7. Apply and verify the migration against the approved Supabase project.
8. Build, smoke test, update GSD state, commit, and push.

## Success Criteria

- Existing opportunities, matches, and documents continue to load after migration.
- Staff can record whether the active pursuit NDA is not required, required, sent, signed, or waived.
- Staff can associate an uploaded NDA document with the active pursuit.
- Repreneurs never see staff-only documents.
- Repreneurs only see approved documents for their own active pursuit.
- Repreneur downloads are blocked while NDA is still required or sent.

## Executive Summary

This plan adds the final Phase 2 control point: document visibility after staff has validated one active pursuit. Staff can now decide whether an NDA is needed and when document access is allowed.

The implementation stays narrow. It does not try to manage signatures or legal negotiation; it simply records the status and protects downloads until Re-New says the basics are satisfied.
